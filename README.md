# Оценка кредитного риска

Оценка вероятности просрочки на 90 дней и более в течение двух лет.

**Автор:** Филиппов Антон Валентинович, М4105.  
**Курс:** Основы методов машинного обучения.  
**Дата:** Модуль 3–4, 2025/2026.

## Бизнес-задача

**Проблема:** банку нужно оценивать риск просрочки перед выдачей кредита. Модель поможет выделять клиентов, чьи заявки требуют дополнительной проверки.
Потенциально это может помочь банку в принятии решения о выдаче кредита.

**ML-формулировка:** бинарная классификация: 1 — серьёзная просрочка, 0 — её отсутствие.

**Целевая метрика:** ROC-AUC. Показывает, насколько хорошо модель различает клиентов с просрочкой и без неё. Дополнительно: Gini = 2 × ROC-AUC − 1, precision, recall и F1.

## Данные

**Источник:** [Give Me Some Credit на Kaggle](https://www.kaggle.com/datasets/brycecf/give-me-some-credit-dataset).

**Размер:** `cs-training.csv` — 150 000 строк × 12 столбцов: 10 признаков, цель и ID. `cs-test.csv` — 101 503 строки без ответов.

**Тип данных:** табличные, все признаки числовые.

**Целевой признак:** `SeriousDlqin2yrs` — наличие серьёзной просрочки.

## Разведочный анализ (EDA)

Первичная проверка CSV показала:

- **Пропуски:** 29 731 в `MonthlyIncome` (19.82%) и 3 924 в `NumberOfDependents` (2.62%). Для логистической регрессии заполнены медианами train с добавлением индикаторов пропусков; бустинг обрабатывает пропуски напрямую.
- **Выбросы:** есть возраст 0 и подозрительные значения 96/98 в числе просрочек. У дохода и долговой нагрузки есть очень большие значения. Специальная обработка выбросов не выполнялась.
- **Распределение цели:** 10 026 клиентов с просрочкой (6.68%) и 139 974 без неё (93.32%). Классы несбалансированы.
- **Корреляции Спирмена с целью:** просрочки 90+ дней — 0.342, 60–89 дней — 0.277, 30–59 дней — 0.257, использование лимита — 0.240. Связь не означает причину.

**Графики:** в ноутбуке построены матрицы ошибок логистической регрессии и градиентного бустинга.

## Feature Engineering

В ноутбуке реализована предобработка для логистической регрессии. Для градиентного бустинга используются исходные числовые признаки с пропусками.

| Действие | Метод | Зачем |
|---|---|---|
| Обработка пропусков | Медианы train и индикаторы пропусков для регрессии; встроенная обработка для бустинга | Сохранить все 150 000 строк |
| Кодирование категорий | Не требуется | Все признаки числовые |
| Масштабирование | StandardScaler только для регрессии | Привести признаки регрессии к одной шкале |
| Новые признаки | Индикаторы пропусков для регрессии | Учесть отсутствие дохода или числа иждивенцев |
| Удаление ID | Исключение `Unnamed: 0` | Номер строки не описывает клиента |

**Разделение выборки в исследовании:**

- Train: 80% — 120 000 строк для обучения.
- Validation: отдельная выборка не выделяется; подбор параметров и порога не выполняется.
- Test: 20% — 30 000 строк для сравнения моделей.
- Стратификация: да, чтобы сохранить долю клиентов с просрочкой.
- `random_state=42`.

Разделяется `cs-training.csv`: в `cs-test.csv` нет ответов для оценки качества. Медианы и масштабирование рассчитываются только по train. В `app/ml/train.py` модель для веб-приложения обучается на всех 150 000 строках; приведённые ниже метрики относятся к разбиению в ноутбуке.

## Моделирование

### Baseline

**Модель:** LogisticRegression с `class_weight="balanced"`, `max_iter=1000`, `random_state=42`.  
**Результат на test:** ROC-AUC — 0.8019, Average Precision — 0.3229, precision — 0.1815, recall — 0.6708, F1 — 0.2857, accuracy — 0.7758 при пороге 0.5.

### Эксперименты

Модели обучены и сравнены на одном разбиении train/test. Порог для обеих моделей — 0.5. Отдельная validation не используется; время обучения не измерялось.

| Модель | Начальные параметры | ROC-AUC, validation | ROC-AUC, test | Время обучения |
|---|---|---|---|---|
| Logistic Regression | C=1.0, class_weight=balanced, max_iter=1000 | — | 0.8019 | Не измерялось |
| HistGradientBoostingClassifier | learning_rate=0.05, max_iter=250, max_leaf_nodes=15, min_samples_leaf=40, l2_regularization=10.0 | — | 0.8688 | Не измерялось |

**Лучшая модель по ROC-AUC:** HistGradientBoostingClassifier; используется в веб-приложении. На test: ROC-AUC — 0.8688, Gini — 0.7376, Average Precision — 0.4081, precision — 0.6059, recall — 0.1840, F1 — 0.2823, accuracy — 0.9375. Бустинг лучше ранжирует риск, но при пороге 0.5 уступает регрессии по recall и F1. Выбор сделан по тестовому сравнению; независимая оценка на новых данных не проводилась.

## Интерпретация

- **Feature Importance:** не рассчитывалась; топ-5 признаков не построен.
- **SHAP:** не используется.
- **Анализ ошибок:** при пороге 0.5 бустинг обнаружил 369 случаев просрочки и пропустил 1 636; ложных тревог — 240, верных прогнозов отсутствия просрочки — 27 755.

**Вывод для бизнеса:** модель подходит для учебной оценки и ранжирования риска. При пороге 0.5 она обнаруживает только 18.4% просрочек. Для реальных решений нужны подбор порога с учётом стоимости ошибок, проверка калибровки и независимая оценка на новых данных. Отсутствие серьёзной просрочки не гарантирует полного возврата кредита.

## MLOps / Инференс

**Сохранение модели:** `app/ml/train.py` обучает бустинг и сохраняет его в формате joblib в `app/models/model.joblib`.

**Инференс:** `app/ml/predict.py` загружает модель один раз на процесс и вызывает `predict_proba`. Flask принимает анкету из 10 признаков, проверяет числа и диапазоны, допускает пропуски в доходе и числе иждивенцев и показывает оценку риска с порогом 0.5. Настройки полей и подсказки вынесены в `app/form_fields.py`.

Исследование: [research.ipynb](ml_research/research.ipynb).

## Запуск веб-формы

Из корня проекта с настроенным виртуальным окружением:

```bash
.venv/bin/python app/ml/train.py
.venv/bin/python run.py
```

Первую команду выполняют для обучения или обновления модели. Затем откройте
http://127.0.0.1:5000, заполните анкету и нажмите «Оценить риск».
Доход вводится в единицах исходного датасета; доли — десятичными числами
(например, 0.5 означает 50%). Доход и число иждивенцев можно оставить пустыми.

Обработчик формы загружает `app/models/model.joblib` один раз на процесс,
передаёт признаки в порядке обучения и вызывает `predict_proba`.
Используется стандартный порог 0.5. После переобучения модели перезапустите
Flask, чтобы загрузить новый файл. Сервер запускается локально в режиме разработки.
